## 评估口径拟定

- 策略展示名 vector 对应现有内部 dense；其余为 bm25、hybrid、hybrid_rerank。四路共享同一版语料、问题、改写、分类条件、生成模型与预算，保留共享改写对期限的计入。
- 期望章节中 + 连接必须命中的组，| 连接组内替代章节，+ 按组切分后各组再解析 |；原始文本别名映射至冻结原文和物理主键，不能直接用字符串 contains 作为最终评分。
- 标准 MRR 是首条相关证据的倒数排名，不能代表跨文档问题的证据已经凑齐。另报组覆盖 Recall@5/@10 和全部组命中率；库外题不进入正例召回/MRR 分母。
- expect_points 的 | 分隔答案要点，不表示这些要点任选一个即可。答案覆盖需核对全部适用要点；Faithfulness 单独核对答案断言与实际提供的证据。
- 有依据的否定回答、证据不足拒答、部分可答，以及模型/裁判调用故障分别记录。拒答不计满分忠实度，错误不伪造得分，显示每个指标的有效分母。
- 旧重排阈值来自 XM 语料，不能当作新 MH 语料的可信门槛。设计需明确公平消融中的共同生成门槛，或先做独立新语料校准并披露线上策略间门槛差异。
- 同一 300 题上四路比较只证明这版语料、标注、模型与配置的结果。不能预设 hybrid_rerank 必赢，也不能把教程数字或“结论不会翻”写成实验结论。

## 后台设计待确认

复用现有评估器，新增运行管理、历史报告、检索/生成分桶表格与图表、逐题召回/证据/答案/裁判详情；任务和报告用持久 JSON 快照，不另换数据库或任务队列技术。运行应可显示进度、取消并清理自有资源，异常保存进度；重启标为中断。执行最多一批评估任务，避免重复点击同时启动全量。先跑分桶小样本检查标注、预算与裁判是否合法，再按冻结的 300 题执行完整比较。后台页面属于前端 Vibe Coding 例外，后端和指标改变仍走已约定的 Superpowers 流程。

### 可选路径与建议

1. 建议：在现有 FastAPI 中封装现有评估器，单运行管理加原子 JSON 快照，CLI 和后台共用指标实现。能在页面查看运行进度、取消和逐题详情，改动集中；应用重启时中断运行保留记录，不声称长任务自动恢复。
2. 轻量路径：继续在终端执行，仅把已完成 JSON 报告放到页面。改动最少，已有预览即采用此方式；不能满足从后台启动和管理评估的完整目标。
3. 独立工作进程或分布式任务队列：适合多人并发及跨进程恢复，但引入部署与调度复杂度。当前只允许一批运行，无此必要。

### 建议冻结的本轮口径

- 保留用户原始 300 题，再生成修订版与逐题变更记录。五桶各 60 题保留；D3/D30 替换为真正无资料依据的问题，原问题转为补充可答回归样例。调整部分 E 类子问题，使全部 60 题确实需要多个小节，不靠强制无关章节点维持桶名。
- 在独立评估资源中使用八篇新材料，保留 8001 当前聊天语料和历史报告。四路共享问题理解结果、过滤条件、生成与裁判模型及已批准预算。
- 为比较检索策略，生成侧四路采用同一套内容充分性自评。在线已有重排分门槛保持；公平消融报告明确标识其生成门槛与线上模式不同，不把旧 XM 的 .82 门槛移植到新 MH 语料。若后续评估线上部署效果，需单列模式并独立校准新门槛。
- 检索输出标准 MRR、证据组 Recall@5/@10、全组命中率；生成输出要点覆盖、Faithfulness、库外拒答、可答误拒答及错误分母。标准要点逐项核对，不把 | 当任选。小样本先验证裁判合法性，失败保留，不能靠删除失败项提升分数。
- 正式后端实现需继续已约定 Superpowers 的设计/计划审查，当前未产生新接口或任务执行代码。
