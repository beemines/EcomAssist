# RAG 评估工作台执行决策与返工代价

对应设计：`docs/superpowers/specs/2026-10-09-rag-evaluation-workbench-design.md`；计划：`docs/superpowers/plans/2026-10-10-rag-evaluation-workbench.md`。以下按实际作出顺序保存控制端的全部 Ruling，阶段记录见 `dev-notes/ch04.md`。它们补清实现契约，不替代真实模型结果，也不授权自动改模型或预算。

| 顺序 | 决策与原因 | 如果判断有误，返工代价 |
| --- | --- | --- |
| 1 | 任务1一次定义计划中的小型不可变公共契约，行为留给各所属任务，避免重复而不一致的类型。 | 调整公共schema并做专项兼容回归。 |
| 2 | dataset_root统一指evals/datasets；dataset_id只由服务器白名单映射到merchant-rag-300，不能当路径解析。 | 调整目录接线及加载器夹具；不放开任意路径。 |
| 3 | 每任务实现者运行一次默认全套，控制端核对实际日志和差异而不重复全套；只有新改动、新失败或最终门禁才扩展验证。 | 漏掉的跨任务回归会在后续全套或最终门禁暴露，须定点修复。 |
| 4 | 仅为冻结题库和八篇评估资料加LF属性，保证Windows检出字节哈希一致。 | 调整限定属性并重新审核冻结资产；原始CSV不能静默改写。 |
| 5 | CaseRecord显式带bucket、difficulty、category、should_refuse和合法回答后的refused，不由空金标推断应拒答。 | 调整DTO/执行器兼容夹具，不改变题目标签或评分含义。 |
| 6 | 合法完成的最终答案即使随后裁判失败，仍可进入拒答率分母；要点覆盖和忠实度排除裁判失败，错误另列。 | 从保存记录收紧拒答分母、重算报告；不重新收费调用。 |
| 7 | 导入前保存计划题目键，缺逐题文件计未执行；得到本轮物理ID映射后才保存完整金标记录，初始化失败不伪造ID。 | 调整初始化、历史投影及恢复测试，不放松金标校验或重跑模型。 |
| 8 | 在资源局部使用固定PyMilvus3.0.2通道接缝计数实际RPC和重连；公开kwargs不能完整保留拦截器，方法计数不能冒充RPC计数。 | SDK变动后调整局部适配，重跑RPC/生命周期专项；不为遥测重跑模型评估。 |
| 9 | 最小增加严格running逐题状态以保存真实中间阶段：前序产品完整，当前和后续为空、无伪造错误；终态规则不变。 | 调整DTO/计数/恢复及活动阶段显示测试，保留已完成产品，不增加模型调用。 |
| 10 | 共用QueryPlan沿用既有Pydantic接口，一次生成、只读使用、检查点复制快照；不另造冻结子类或改业务字段。 | 为将来的误修改消费者补专项回归并修复，不改变协议或收费重跑。 |
| 11 | RunConfig新增严格出处：资料四类哈希、实际Prompt内容和端点摘要、传输期限及token字段；旧记录可读但不能放行新全量，指纹不含scope但含实际安全配置。 | 修复配置/存储/历史兼容并从保存记录重新导出，不隐藏预算或模型变化。 |
| 12 | 管理器在清理后、终态manifest前分别原子发布公开JSON/Markdown，聚合文件各128MiB；API只读取，不能把逐题2MiB上限套在全报告上。 | 调整导出格式、上限和规模回归，完整保留证据与部分状态，不收费洗分。 |
| 13 | GET及试运行资格查询使用生产者真正不写盘的读取；计数诚实派生，保留持久时钟，授权恢复/写入兼容。禁用模式不只是不启动任务，也不能修历史文件。 | 修复存储缓存、恢复和API兼容回归，不重新调用模型。 |
