# 系统架构

## 在线请求

浏览器通过FastAPI创建/读取会话，以SSE接收状态、来源引用、文本增量和最终消息身份。默认实现由LangGraph Workflow协调意图、业务状态和有界Agent；早期单次Function Calling实现与实验记录仍在Git历史和步骤文档中。

知识请求经过查询理解、Dense/BM25双路召回、RRF融合及精排。证据检查位于知识检索之后、进入生成Agent之前；置信度不足返回兜底并记录问题与检索快照。通过检查后生成仍有知识充分性与引用校验。鉴权、超时、结构非法或取消分别保留错误状态，不伪装成正常拒答。

业务工具通过统一注册、策略、参数校验、预算和执行审计调用。本地工具与独立MCP Server共享执行边界。工单与退款申请生成预览，用户明确确认后按真实会话/消息身份提交；重复确认不重复创建。退款只登记申请，不触发资金处理。

## 数据职责

| 存储 | 职责 |
| --- | --- |
| MySQL | 会话、消息、知识原文、工单/退款、审核、评估轮次和主题结果 |
| Milvus | Dense/BM25检索索引；主键对应MySQL知识行 |
| SQLite checkpoint | Workflow持久状态、会话恢复和工具/行动连续性 |
| 本地Langfuse | 请求trace树、节点/模型观测、Token与耗时 |
| 本地私有文件 | 冻结数据、预算账本、训练权重、批次回执与人审材料 |

知识双写采用pending/done状态。向量写入并读回核对后才把知识标记完成，失败可按同一主键恢复。不能把向量ACK、数据库提交和任务状态合并成一个虚假的原子事务。

上下文保留当前问题、必要业务状态、分层摘要和完整近期轮次；预算计算包含工具Schema、检索证据与输出预留。摘要和恢复有自己的归属与处理记录。

## 问题池与数据飞轮

三个入口分别保留来源：检索置信度低、生成自评不足、用户反馈未解决。落池保存当前轮检索片段和分数；👎按该轮checkpoint尽力回捞，没有执行检索的轮次允许NULL。NULL与检索零命中的空数组不是同一状态。

飞轮将原话改写为标准问题，生成建议答案，和待审队列查重；同一缺口累加次数，原话通过`matched_review_id`关联。审核详情保留原话及当时证据，人工核准后走既有知识入库与向量化流程。发布失败可用原知识身份重试，不重复新增缺口。

## 主题分类旁路

`app/topics`负责脱敏、来源、费用控制、review契约、数据库与统计；`ml/topic_classifier`负责独立依赖、分层数据、HFL全参训练、验证选模/阈值、留出评测、导出与CPU推理。两个环境共享轻量术语契约，应用主进程不导入Torch。

旁路批次先冻结ID边界、问题hash、模型版本和库身份，再执行本地推理与落表。唯一`question_id`保证一条问题对应一条当前结果；旧版本重分类需要显式范围。原文变化、身份不匹配、空预测或无效概率保留失败/待复核，不用最高分硬凑“其他”。

主题页统计当前有效结果，旧模型、输入失效及未知标签不混入。分类器输入仍为经过清洗的池原话；查看归并FAQ是审核能力，没有偷偷改成另一种训练/推理分布。

## 观测与评估

Langfuse回调挂在图编译入口，请求关联会话、意图与受控元数据。成本汇总按模型generation计算，避免父节点重复记账；未知usage不算零。

RAG工作台比较检索策略与生成质量；评估流水线把每轮指标及有效分母写入`eval_runs`，只在可比配置上展示趋势。定时默认关闭，界面GET与报告查询不启动收费评估。

当前验收页的模型指标是带时间/模型身份的保存报告，主题数量读取当前统计；历史报告和实时在线健康状态分别显示，避免将旧成绩误当成当前服务探测。

## 部署边界

当前是本地单机工程，示例服务绑定127.0.0.1，应用保持单worker。进程内会话锁、文件/数据库任务归属和受管启动脚本不是横向扩容方案。生产认证、租户隔离、外网接入与多实例调度需要独立设计。

追踪可自部署；LLM、嵌入与重排仍按供应商配置执行，并非整个系统完全本地推理。密钥、原话、trace和权重的公开边界见[安全说明](../SECURITY.md)。
