# 第九步手动验收

先按 `docs/ch09-local-demo.md` 启动正常8006与本地Langfuse。以下均新建测试会话，保留自己的原话；本轮真实结果以 `docs/superpowers/reports/2026-10-19-observability-flywheel-acceptance.md` 为准。

## 1. 看一条完整trace

1. 在客服页点击“开启新对话”，发送“订单1001的物流到哪儿了”。
2. 等完整回答结束，应看到物流工具状态；若当前工具参数采用订单号直查，不强求先出现额外订单工具。MCP服务需已启动8101/8102。
3. 在Langfuse进入项目EcomAssist CH09，打开Observability → Tracing，按最近时间或会话筛选。
4. 展开根 `ch09.execution`，应能看到图节点、指代/意图模型、订单查询、`source=mcp:logistics`的工具操作、最终回答模型。
5. 点模型generation看实际prompt、输出、usage、耗时；工具span本身不重复计模型tokens。后台摘要、标准化、发布、评估使用各自purpose。

## 2. 跑完一次补知识闭环

1. 新对话问一条明确的、知识库尚无的政策问题，例如验收专用模拟服务的押金和归还期限。不要重复使用已完成验收并已入库的那条问题来证明“首次缺失”。
2. 应得到知识不足兜底。打开“知识审核与观测”，点击刷新，等待后台标准化/查重入待审队列。
3. 点击“查看原话与证据”。核对完整原话、入池入口、当时片段正文及分数、是否送模。没有检索、检索为空、旧轮无法回捞会明确区分。
4. 人工填写标准问题、知识分类和核准答案。分类要与原提问的分类过滤一致；没有分类过滤的聊天可选择清楚的业务分类。示例答案只是参考，不自动复制为核准答案。
5. 示例核准答案应注明“【验收模拟政策】”，并给出本次测试的明确事实；不要把未经审核的真实承诺写入库。
6. 点击通过，先显示“等待入库/入库中”；点击详情“刷新状态”直到“已入库·可检索”。失败不能当成就绪，修复原因后可点“重试入库”，原知识ID不变。
7. 另开新对话问同一个问题，应根据新检索到的人工答案回答。打开trace核对知识片段，不能靠上个会话记忆作答。

## 3. 负反馈与查重

1. 找一条已完整结束的回答，点👎。
2. 只有后端保存成功后显示“已反馈·将用于改进”。失败提示“未保存”，可以重试。
3. 刷新历史再点同一条，后端不重复写同一入口；同一轮从自评、检索、反馈多个入口进入同一缺口，出现次数只计一次。
4. 在新轮用同义问法再问并反馈，待审缺口应合并且增加出现次数。商品型号、否定、适用条件不同的不能硬合并。
5. 点旧轮的👎，详情必须是旧轮问题和旧轮证据，不能拿当前轮或最新知识替换。

## 4. 对比意图Token

在新会话分别问物流、知识政策、闲聊。审核后台切到“意图Token”，选择包含这些请求的本机日期和分钟后查询。核对用途/意图、请求数、模型调用数、实际、估算及未知usage。分类前的模型消耗归入最终意图；只有完成的执行计入汇总，重放不双计。后台用途独立列出。

费用没有可信价格数据时显示N/A，不能据此当成0元。Langfuse导出可能有短暂延迟，统计有60秒缓存；稍后刷新，而不是反复发送收费聊天。

## 5. 两轮评估趋势

后台“评估趋势”选“留出20题”，手动运行会明确提示费用。每轮完成后再启动下一轮，每轮一个新UUID。确认每轮dataset_size=20、逐题报告、完成/失败分母及Faithfulness至少一个有效样本。切到“冻结300题”不应把20题成绩冒充全量。

同配置曲线在当前页展示，失败或N/A留断点；模型/预算/Prompt/语料变化会产生不同配置分组。既有四策略工作台仍在 `/rag-eval`，它不是本章的自动评估结果表。

## 常见情况

- 看不到文件或配置：确认PyCharm打开的是本章worktree，详细见PyCharm指南。
- 只有pending：点详情“刷新状态”，核对安全错误；不得仅凭“审核通过”认为可检索。
- 上游额度不足：先恢复对应API的可用额度，再对选中任务显式重试；验收硬上限不能充值或重启重置。
- 服务未启动：看本工作区 `.cache/observability/*.err.log`；不要结束不明PID。
- 需要数据库证据：使用UTF8只读脚本按单个会话、审核记录或run_key查询，不用PowerShell5.1默认解码JSON。
