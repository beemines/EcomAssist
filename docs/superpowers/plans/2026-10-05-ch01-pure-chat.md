# Ch01 Pure Chat Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 建立可通过 curl 演示的电商客服多轮 SSE 对话与售后 JSON 提取后端。

**Architecture:** FastAPI 路由调用独立的会话/预算、Prompt、模型服务。会话按 session_id 存于单进程内存；ChatOpenAI 直连 .env 配置的 OpenAI 兼容 Chat Completions 上游。提取使用 JSON 模式与 Pydantic 校验，不读写会话。

**Tech Stack:** Python 3.13（已检测本机 3.13.5）、FastAPI、LangChain 官方 core/openai 包、Pydantic v2、pydantic-settings、Uvicorn、HTTPX、pytest；uv 管理依赖并生成 uv.lock。

**Spec:** `docs/superpowers/specs/2026-10-05-ch01-pure-chat-design.md`（用户已批准）

**Execution:** 用户已选择 Subagent-Driven；保留该选择，不再次询问执行方式。实现前用户审阅本计划，并确认隔离工作树或当前目录开发分支的工作位置。

## Global Constraints

- 使用 Python、FastAPI、LangChain；模型调用统一使用 OpenAI 兼容 Chat Completions 接口，直连所配置的上游。
- 使用 LangChain 的 `PromptTemplate` 和 `with_structured_output`。
- 不加入业务工具调用、Agent 循环、模型代理网关、数据库、知识库或检索。
- 本章通过 curl 验收，当前不包含聊天页面；后续页面按用户的 Vibe Coding 例外处理。
- 输入预算默认 2,000 个估算 token；输出上限默认 512 个模型 token，二者独立配置，并要求配置值为正数。
- `session_id` 必填、1–128 字符、不得全空白；`message`/`text` 必填、不得全空白、最多 20,000 字符。
- 只保留完整 user/assistant 轮次；system 与当前问题不得裁断；必留内容超预算返回 422 `input_too_long`。
- 同会话并发返回 409 `session_busy`；失败、断开、空回答和已知截断不提交半轮。
- SSE `delta` 文本增量、成功一次 `done`、失败一次 `error` 后关闭；不将每块等同单个 tokenizer token。
- 提取三个键均必填：`order_id: str | None`、`request_type` 枚举、`expected_solution: str | None`；缺失值为 null/unknown，额外键禁止。
- `request_type` 为 refund/return_refund/exchange/repair/logistics/other/unknown；expected_solution 使用原文短语。
- 显式 `with_structured_output(method="json_mode")`，不自动换协议、工具调用、模型或删除格式约束。
- 可单测代码走 TDD；纯 Prompt/标注数据通过样例评估验证，不写模板内容快照来冒充效果验证。
- 具体库/API 用法在每个任务动手前查 Context7 MCP。项目研究文档可复用；首次使用未覆盖 API 时补查。
- 每个任务完成、计划审阅通过、code review 与 finish 即时追加 dev-notes/ch01.md 四项记录。
- 禁止输出真实密钥或读取其他项目凭据；只使用本项目 .env。代码测试不得请求真实上游。

### Task 4: 多轮 SSE 对话与流生命周期

**Interfaces:**
- 样例每行 `{id,text,expected:{order_id,request_type,expected_solution}}`，至少 20 条、覆盖全部枚举/缺失/歧义/多订单/格式注入；标签由原文产生，不由模型自造。
- `async evaluate(base_url: str, cases_path: Path, output_path: Path, *, http_client: httpx.AsyncClient | None = None) -> dict` 调实际 /api/extract；`score_cases(records: Sequence[dict]) -> dict` 计算有效率/字段准确率/缺失值及原文约束，不把错误响应计为通过。注入客户端仅用于离线测试，正常 CLI 建立真实 HTTP 客户端。
- 每个计分 record 明确包含 id、text、expected、status_code（传输失败为 null）、response（三字段对象或 null）、error_code（成功为 null）。有效样例须 HTTP 200、无 error_code 且通过三键 schema 校验；报告含 total、valid_count、valid_rate、order_id_accuracy、request_type_accuracy、expected_solution_accuracy、failures，各字段准确率分母均为 total，失败样例记错不跳过。
- 缺失值计分以 gold 中 order_id/expected_solution 的 null 和 request_type 的 unknown 各字段位置计数：missing_value_total、missing_value_correct、missing_value_accuracy。原文约束以样例计数：source_constraint_total=total，source_constraint_correct 要求有效输出且全部非 null 订单号/期望方案为原文片段，报告 source_constraint_rate。任何分母为 0 时对应率为 null，不能伪造 100%。输出字段准确率不等同整章验收通过，不新增用户未指定的准确率阈值。
- `async smoke(base_url: str, output_path: Path, *, http_client: httpx.AsyncClient | None = None) -> dict` 报告 passed、failures 和各场景证据：两轮各有至少两个非空 delta、恰好一次 done 且为最后事件、无 error；第二轮包含第一轮提供的固定订单号；提取恰好三个键且符合 schema 和给定描述。报告实际配置的上游/模型/版本、首增量时间和未实测上游，不存密钥；记录的配置不冒充上游自行返回的身份。
