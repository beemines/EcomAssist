# 第八步设计：即插即用工具系统与 MCP

日期：2026-10-18。设计基线：master `8e049fe`，已包含第六、七步；实际实施基线为后续文档提交`8b10255`。状态更新于2026-10-19：书面设计及实施计划已获用户批准，按Native顺序实现；代码和一次独立后端审查修复已本地提交。截图主流程及此前两个组合失败原句已真实复验通过，实际版本/范围见[最新复验报告](../reports/2026-10-19-pluggable-tools-reacceptance.md)，原裁定和失败保留在[初次报告](../reports/2026-10-18-pluggable-tools-acceptance.md)。本章整合选择尚未提出。

## 1. 目标与已确认范围

让现有客服的内置和外部 MCP 工具共享注册、校验、权限、执行与审计；新增工具通过注册在下一轮对话中生效，无需修改客服核心代码或重启客服服务。聊天中的建工单请求由 Agent 补齐必填信息，经过持久化预览确认后才写入现有 tickets 表。

用户明确确认：

- 当前无可调用的 Context7 MCP，允许本章使用官方文档和对应版本源码核对并记录来源。
- MCP 新工具使用本地逐工具授权、策略热加载；发现不等于授权。验收中可以登记本地策略，不需要改客服核心源码或重启客服服务。
- 固定 `mcp==1.30.0`、`langchain-mcp-adapters==0.3.2`。最新 SDK 2.3.0 不满足适配器的 `<2.0.0` 依赖要求，用户选择兼容的单环境方案。
- 每轮边界发现并固定清单、统一执行与审计、两个独立 mock Server、原生工单预览确认/取消，原投诉按钮表单流程保留。
- 前端工单预览卡片按 Vibe Coding 例外，以现有主题和页面效果验收，不执行前端 brainstorm、TDD、code review 流程。后端仍走 Superpowers、TDD 与审查；Prompt 变更以标注样例验证。

本章不做 Skill、更多外部系统、真实物流接口、真实退款、跨会话画像，也不重复建设前三层上下文管理。

## 2. 方案选择

| 方案 | 特点 | 本章取舍 |
| --- | --- | --- |
| 每轮边界发现 + 本地策略热加载 + 本轮固定清单 | 每轮有发现请求；新增工具下一轮可见；并发与恢复的边界清楚 | 采用，两台本地 Server 的规模适合此方案 |
| 后台轮询与缓存目录 | 减少发现请求；需要处理刷新延迟、任务生命周期及旧缓存 | 暂不增加这层复杂度 |
| 依赖 Server 工具变化通知 | 通知及时，但 Server 重启、断线与未发通知仍需补发现 | 不把通知作为正确性前提 |

运行形态是一个客服进程、一个物流 MCP 进程、一个售后 MCP 进程。建议演示端口为客服8005、物流8101、售后8102，可配置；实施时先核验占用，保留正在运行的8004及其原始证据，不接管不明进程。

## 3. 统一注册目录

### 3.1 工具描述与本地策略

每个工具至少具有模型可见的名称、用途描述、JSON Schema 参数定义。目录另外保存可信的来源、公开名与原始名映射、读写类型、可用意图/场景、结果投影规则、超时与只读重试上限、需要的可信身份约束、定义指纹。

权限来自本地受控策略文件，不读取外部的 readOnlyHint、描述或模型输出作为授权。唯一可写工具是既有内置 create_ticket；外部工具只有按本地条目批准的只读工具可用。外部工具不能通过同名、别名或“只读”声明冒充 create_ticket。

策略文件可配置 MCP Server 连接与逐工具授权、内置插件入口。热加载必须先完整解析、校验并构造新目录，再发布不可变版本；不能发布一半的新目录。非法策略或名称/Schema冲突必须明确记录并拒绝受影响的调用，不能静默覆盖工具。没有可用策略时不授予写权限。

注册时拒绝空描述、非法名称、无效 Schema、未解析的外部引用和公开名冲突。公开工具名满足模型接口长度与字符限制。Server 名不来自模型参数。

### 3.2 内置工具的热注册

现有订单、商品、FAQ、工单工具在启动时登记；原本地 query_logistics 不再登记。保留其历史消息的回载和展示，不把旧调用历史改成 MCP 来源。

新增内置工具可以放在新的插件模块中，通过本地注册配置声明入口与读写策略；目录加载器按注册入口加载它，Agent和执行器无需新增名称分支。本章保证新增插件模块和新增注册即时生效，不对执行中的 Python 模块做原地重载；已有工具更新可使用新的模块版本入口。普通聊天请求和 MCP 返回内容均不能指定 Python 导入路径。

本章需要消除 app/workflow/agent.py、controls.py 中写死的读取名单和固定工具 Schema 对新增工具的阻碍；固定业务流程仍可使用本地登记的能力标识，不能让新增工具都去改核心 if/else。

### 3.3 MCP 发现、隔离与本轮快照

使用同一个 MultiServerMCPClient 的多 Server 配置，分别调用 get_tools(server_name=...)，并发发现、隔离单个 Server 失败。每轮开始先加载策略再发现，只将本地授权且契约有效的工具合并进有效目录。

每轮只构造一次目录快照，预检和实际模型绑定使用同一个版本，避免目前“预检/执行 Schema 不同”检查与热更新冲突。新注册工具在下一轮生效，已经开始的轮次不更换工具实现或参数定义。执行前仍重新检查本地撤权；本轮固定定义不意味着撤权失效。

Server 下线或发现失败时保留来源明确的错误状态，其他 Server、内置工具和聊天仍可使用。不退回随机的内置物流实现，不把旧查询结果冒充本轮新结果。服务恢复后下一轮重新发现，不要求重启客服进程。

## 4. 统一执行引擎

所有正常工具调用、参数拦截和权限拒绝都由统一入口结算。调用上下文包含可信会话、原用户消息、当前业务意图、目录版本和服务端确认凭据；这些字段不暴露给模型填写。

执行顺序：查目录与本地权限 → 校验模型参数 → 注入可信上下文 → 执行业务工具 → 规范化结果 → 尽力写审计 → 返回 ToolOutcome/ToolMessage。

### 4.1 校验与错误反馈

- 统一按模型可填写的 JSON Schema 校验，不做字符串转数字等隐式类型转换；内置原有严格 Pydantic 与非空白约束继续保留。
- 使用 jsonschema 的对应 draft 校验；本章的工具契约以受支持的对象 Schema 为边界，本地引用先校验，禁止校验时外取远程引用。
- 模型传入隐藏身份、确认标记、注入的调用标识或其他禁止字段时拒绝，不使用模型的值覆盖服务上下文。
- 错误以固定错误码、字段路径和可供纠正的说明回灌，避免将模型可纠正的缺参/错参直接变成整轮结构化异常。
- 工具原生调用协议仍严格校验；正文伪造的工具 JSON 不转换成真正调用。第七步的一次模型生成恢复不重放工具或写操作。

### 4.2 超时、重试与结果

读工具仅对连接暂时故障、规定的暂时 HTTP 错误和超时有限重试，默认最多一次。业务未找到、参数错误、权限拒绝、永久错误和调用方取消不自动重试。create_ticket 的重试上限强制为0，配置或外部声明不能将其调大。

三类错误分别为 invalid_arguments、not_found、工具故障；引擎同时保留安全的细分错误码。最终超时的状态是 timeout，审计记录真实重试次数和总耗时。若第一次超时、第二次成功，最终状态success、retry_count=1，并在安全执行摘要中保留首次故障类型。

MCP 适配器返回的 content 块、ToolMessage.status、artifact.structured_content 和执行异常要显式转换为现有字典结果，不假设 MCP content 就是原来的 JSON 字符串。失败结果不能被格式化成成功。

结果按本地投影规则挑选回答所需字段、翻译已知枚举、限制大小，并以 ensure_ascii=False 序列化。模型可见结果、上下文 token 计算和历史工具结果使用同一份规范化副本；原始业务数据不因格式化被回写。安全错误不向模型和审计表泄露认证头、连接密码或异常堆栈。

写操作超时表示结果未确认，不能声称已失败且绝未写入，更不能自动再写一次；工单的后续核对复用原始调用身份和现有幂等编号。

## 5. 两个业务 MCP Server

使用官方 SDK 1.30.0 的 FastMCP，Streamable HTTP，独立启动。选择无状态 HTTP 模式用于这些独立 mock 查询；按照1.x构造器和运行接口配置，不抄写2.x接口。

| Server | 初始工具 | 行为 |
| --- | --- | --- |
| logistics | query_logistics | 根据订单号生成随机模拟物流状态与轨迹，明确 mock 来源 |
| aftersales | query_warranty、query_return_progress | 根据订单号生成随机模拟在保信息、退货处理进度，明确 mock 来源 |

Server 不连接 MySQL、不建表、不接真实业务系统。可由本地配置设置随机种子以重现故障测试，但正常演示仍是 mock。

客服端在涉及订单的外部查询前，以当前 SQL 会话身份和既有订单提供器核验归属；不让模型或外部 Server 选择用户身份。随机 MCP 轨迹和售后进度不覆盖既有订单快照，不用于替代第六步退款资格判断的订单/政策事实；跨轮随机变化必须一直保留模拟提示。

新增 MCP 工具的演示先登记本地策略、再仅重启相应 Server，下一轮发现并绑定新工具。用 PID、目录版本、实际远程调用日志验证客服未重启；不能用固定成功响应或直接调用 Server 代替 Agent 验收。

## 6. 工单的两种确认入口

### 6.1 聊天明确请求

在现有八类意图基础上新增“工单”，覆盖明确要求创建或提交工单的表达和补齐信息的延续轮。明确否定不授权；仅要求转人工不自动解释成同意建工单。混合投诉中若明确要求建单，按工单请求处理；没有明确建单请求的投诉继续原投诉流程。

Agent 使用当前原文和本会话可追溯的用户信息组织描述，缺描述时先追问，不能把模型编造的事实写入工单。工单类型限既有售后、投诉、咨询。必填业务字段校验通过后才生成可确认提案；模型填入 approved=true 等字段没有授权效力。

流程：Agent 产生合法 create_ticket 申请 → 独立准备预览节点保存不可变参数与调用身份 → 父图 await_ticket_confirmation 节点 interrupt → 前端确认/取消 → 公开恢复接口核验 → 引擎授权后实际写入或生成拒绝结果 → 配对工具结果与最终回执。

等待确认的提案不视为已经执行。直接绕过暂停恢复入口、没有可信确认凭据的实际 execute 调用由引擎拒绝并记审计。图中的暂停信号不能被执行器普通异常捕获吞掉。

### 6.2 预览、恢复与幂等

预览保存 conversation_id、原 user_message_id、tool_call_id、内部 confirmation_id、规范化参数和参数指纹；卡片返回工单类型、问题描述及实际暂停根 checkpoint_id。前端只回传定位信息和 confirm/cancel，不回传可覆盖预览的新业务字段。

新增接口约定：

- `GET /api/conversations/{id}/pending-ticket`：只读当前有效根，返回 `{pending: null}` 或含 turn_id、confirmation_id、checkpoint_id、ticket_type、description 的预览，支持刷新/切换会话恢复。
- `POST /api/conversations/{id}/actions/confirm-ticket`：仅接受 turn_id、confirmation_id、checkpoint_id、decision（confirm/cancel），通过预检后返回现有托管SSE。沿用原确认接口的同源、JSON和安全错误边界。
- 原 `POST /api/conversations/{id}/actions/ticket` 保持字段与表单语义，不重用新接口冒充原按钮确认。

恢复入口在同一会话锁内核对最新根、根命名空间、interrupt载荷、会话归属、原轮 SQL、目录/契约指纹和本地当前权限。历史根、其他会话、参数篡改、过期确认、重复状态冲突均不能写入。

- 确认：授予仅适用于这一申请和参数的服务端确认凭据，execute调用create_ticket；复用现有 TicketRepository 的会话/用户消息/tool_call_id 幂等编号与短事务，同一申请至多产生一张工单。真实成功才回复返回的工单号。
- 取消：不调用仓储写入，生成permission_denied工具结果、写拒绝审计，关闭本次提案并正常回复已取消。
- 重复点击或响应丢失：已完成回执以只读方式重放，不产生新的模型申请或再次创建；不将“重复确认”变成一个新的 tool_call_id。
- 服务重启：从原检查点恢复待确认状态，不重新让 Agent 生成提案，不把运行期客户端持久化。
- 目录更新：原轮保存纯数据工具清单manifest，恢复按该manifest重建并核验相关工具契约与当前授权；无关工具新增不扩展本轮清单，相关工具删除、改Schema或撤权明确报冲突，不能把新定义套在旧预览上执行。
- 新用户轮次替代待办：旧提案失效，按权限拒绝结算，不允许旧卡片继续写入；保留历史原文和失效状态。

准备预览、等待确认和真实执行分成独立节点；等待用户的墙钟时间不消耗活动执行预算。恢复时继续原轮次的模型费用、决策次数和一次恢复标记，不能通过暂停重置费用或重试额度。SQL和检查点不是同一事务，故不声称分布式 exactly-once；通过稳定身份、仓储幂等和持久回执防重复建单。

成功/取消回执可由真实执行结果确定性构造，避免模型在写库后编造工单号。错误结果仍形成配对 ToolMessage，模型解释故障时不能再次自动申请写操作。

### 6.3 原投诉按钮

保持当前交互和接口：完成回复的“建工单”按钮打开原自填表单，用户选择类别、填写描述并提交。已有这次表单提交就是确认，不再叠加新的工单预览。

TicketActionService 继续验证原完成根、suggested_actions、SQL原回复与会话身份，并向统一引擎传入服务端派生的既有表单确认凭据。旧按钮不因当前原话没写“建工单”而被错误拒绝；这是用户明确保留的确认入口。两种确认凭据不能由模型参数模拟。

退款申请仍走第六步已有独立表单服务，不给 Agent 增加退款写工具，也不改变真实退款未执行的范围。

## 7. 审计落库

新增 tool_audit_logs，无外键，独立短事务。字段至少为：

| 字段 | 建议类型/含义 |
| --- | --- |
| id | BIGINT UNSIGNED，自增主键 |
| conversation_id | BIGINT UNSIGNED，可空以记录缺少合法上下文的拒绝，无外键 |
| tool_call_id | VARCHAR(64)，原逻辑调用标识 |
| tool_name | VARCHAR(64)，模型调用的公开名 |
| source | VARCHAR(128)，builtin、mcp:logistics、mcp:aftersales，未知来源明确标记 |
| arguments | JSON，模型业务参数；无法解析时记录安全诊断对象 |
| result_summary | TEXT，安全、有限长的结果摘要 |
| status | success、failed、timeout、validation_blocked、permission_denied |
| error_code / error_message | 可空安全错误码、有限长说明 |
| retry_count | 非负整数，首次执行为0，写操作固定0 |
| elapsed_ms | 非负总耗时，包含同次逻辑调用的重试 |
| created_at | DATETIME，记录时间 |

按会话与时间、tool_call_id建立普通索引；不假设模型的调用ID跨会话全局唯一。一次执行器逻辑调用结算一条，内部只读重试汇总；等待前端时保存的是提案，取消/拒绝也必须结算审计。正常尚未完成的提案不能提前记成成功。

审计使用与工具业务分离的 Session/事务、有限写入时限。审计连接失败、表不可写或超时只发安全告警，不回滚已提交工单，不把成功改为失败，也不强行放行被拒绝的动作。不承诺审计数据库故障期间仍然绝无缺行，故障明确留 log/app.log。

迁移提供显式migrate和只读verify，在线启动只验证，不悄悄执行DDL。测试只在独立测试库/随机测试schema内建清理表；演示库的DDL先核对身份，不重复或破坏已有表。

## 9. 验证与交付

后端单元/契约测试按TDD，Prompt/意图使用含否定、多轮补充、混合投诉的标注集，前端只做用户例外允许的实际页面验证。

| 验收 | 必须具备的证据 |
| --- | --- |
| 新内置工具 | 新插件与注册记录，客服PID和核心代码不变，真实Agent调用、执行器及审计对应 |
| 两Server接入 | 三个独立进程，物流经MCP轨迹工具、售后经在保/退货工具；不出现旧内置同名工具 |
| MCP新增工具 | 本地策略登记、只重启相应Server；客服PID不变，下一轮目录新增且Agent实际调用 |
| 工单确认 | 无描述先追问；预览参数有用户来源；确认后tickets新增恰好1行、回复编号与行一致 |
| 工单取消 | 未新增工单，create_ticket审计permission_denied，原预览不能再执行 |
| 读超时 | 用本地故障注入，不依赖真正网络波动；实际尝试数、最终timeout、retry_count=1和耗时可查 |
| 写超时 | 真实执行入口受控延迟/故障，仓储尝试数至多1、审计retry_count=0；不伪称绝无提交 |

额外合同覆盖：JSON Schema边界、未知/重名工具、假只读声明不授权、直接未确认调用、确认篡改与重复、原投诉表单、审计故障不阻断业务、会话刷新恢复、暂停不重置费用、旧历史回载与上下文Schema预算。

先做无模型的本地SDK/HTTP协议、独立MySQL和故障测试，再做少量页面完整链路验收；所有真实GLM/BGE、后台摘要和失败请求计数，不跑上百次评估，不把验收上限留给普通交互入口。每个已完成后端任务做范围验证与必要审查，最终源码冻结后跑一次完整回归，避免无新变化重复整章审查/长批次。

交付包含：锁文件、两Server源码、热注册策略与样例插件、统一执行/审计、显式迁移与验证命令、聊天确认流、演示启动命令、实际测试报告及dev-notes/ch08.md。既有第七步未全部通过的长验收不因本章完成而倒改。
