# 第十步设计：飞轮问题的多标签主题分类器

日期：2026-10-21。基线：`master 3ad30a5`，已合并第九步。本文首版提交为`bb89ce0`，用户已审阅并明确回复“批准设计，编写实施计划”。状态：书面设计已批准，实施计划编写中；尚未开始实现。

## 1. 目标、已批准事项与范围

把飞轮积累的低置信度问题批量归入17个主题，让运营人员从主题分布看出应优先补哪块知识。分类器只辅助后台整理，不替代知识审核，不改变实时聊天的意图识别、检索、工具或确认流。

用户已确认：

- 固定使用哈工大讯飞 `hfl/chinese-roberta-wwm-ext` 全参数微调，不使用LoRA/QLoRA，不做embedding或意图模型微调。
- 采用本机训练、独立Transformers推理服务、批量旁路写表的方向；ONNX作为已比较但本步骤不采用的方案，不额外维护两套推理后端。
- Context7当前不可调用，本步骤允许查官方文档与锁定版本源码核对API；技术选型不变。
- 造数、预标注及其修复/重试累计最多人民币10元，账本独立于第九步，重启不清零。
- 先做小批人工抽审再扩量；同义问题分组后划分数据；原DDL保留，必要追溯补充字段在设计中明列。
- 前端沿用聊天页的浅色、绿色和圆角风格，适用用户的Vibe例外，不套前端brainstorm、TDD、code review流程。

本步骤交付一条完整链路：问题池快照 → 清洗和LLM预标 → 人工抽审 → 分组分层划分 → 训练集增强 → 全参训练 → 冻结评测 → 本地服务 → 真实池批量归类 → 主题分布。大模型只用于离线数据准备，推理服务不调用大模型。

## 2. 已核实基线与资源

训练和推理使用独立Python3.12环境，依赖由独立项目及lock固定，业务主环境不引入torch。实现计划阶段核对PyTorch CUDA wheel、Transformers、Accelerate、NumPy、scikit-learn和iterative-stratification的具体发布版本及源码签名，生成可复现锁文件后安装，不使用浮动latest。

## 3. 单一权威术语表与标注规则

唯一可编辑来源为拟新增的 `config/topic-taxonomy.json`，版本及内容hash一起进入数据、prompt、模型包、服务响应和统计。训练、预标注、校验及页面均从该表生成，不各抄一份标签。模型包携带的是该表的冻结副本，加载时核对hash，不构成第二份可修改权威表。现有知识块的category是文档标题路径，不把它冒充主题标签，也不批量改写历史路径。

按用户顺序固定index 0–16：

| 标签 | 边界说明 |
| --- | --- |
| 退换货 | 退货、退款、换货及其条件和进度；维修诉求另标保修维修 |
| 物流 | 发货、配送、包裹位置、签收与丢件；费用金额另标运费 |
| 尺码 | 大小、尺寸、适配、尺码选择及尺寸不合适 |
| 发票 | 开票、抬头、税号、发票内容与获取方式 |
| 质量问题 | 损坏、故障、瑕疵及质量投诉；只说退或修不推断存在质量问题 |
| 运费 | 寄送、退回的运费金额、承担方或包邮；货的位置归物流 |
| 优惠活动 | 优惠券、满减、折扣活动及使用条件；购买后补差价归价保 |
| 价保 | 降价保护、价格差额返还及申请条件 |
| 支付 | 付款、支付方式、支付失败或重复扣款；退款诉求归退换货 |
| 订单修改 | 改订单地址、收件人、规格、数量等；仅问配送状态归物流 |
| 库存补货 | 有无库存、缺货、补货和到货提醒 |
| 商品信息 | 商品材质、成分、功能、使用或养护等信息；明确尺码诉求归尺码 |
| 保修维修 | 保修范围、期限、寄修、维修及维修进度；退回或换新另标退换货 |
| 账号 | 注册、登录、身份验证、账号资料及注销 |
| 会员积分 | 会员权益、等级、积分获取、消耗或失效 |
| 评价 | 评价发布、修改、追评及评价相关权益 |
| 其他 | 字面存在的诉求均不属于前16类；不表示模型没把握 |

一句中每个明确诉求都保留，按权威顺序输出去重标签。提到的名词不等于独立诉求，不凭常识补因果；否定、纠正及“不要做X、只做Y”不能误当成要求执行X。

规则样例：

- “买大了想退” → `["退换货","尺码"]`。
- “坏了，想退货” → `["退换货","质量问题"]`；“给我寄修” → `["保修维修"]`。
- “包裹到哪了，退回要付多少邮费” → `["物流","运费"]`。
- “刚买就降价了，能补差吗，还有券可以领吗” → `["优惠活动","价保"]`。
- “不要退，我只想修” → `["保修维修"]`。

“其他”与前16类互斥。若存在已覆盖诉求，只标明确命中的业务类目；混合句中超出类目范围的剩余信息记录在标注备注，不增加“其他”。无法清洗、语义残缺或标注有争议的样本进入隔离清单，不硬造标签。

## 4. 语料、规模与人工参与

### 4.1 快照与清洗

导出命令先preview，execute冻结数据库身份、ID范围、高水位、时间和行数上限；该清单控制本次数据准备，不在后台持续吸取新原话。保留question_id及入池来源、逻辑轮次定位；真实/演示/合成/来源未核实是独立字段，不用入池入口冒充真实性。

本地先脱敏手机号、证件、邮箱、详细地址、订单/运单等个案标识，保留尺寸、金额、型号及否定等分类所需语义。姓名和不确定敏感片段需人工检查或隔离。规范Unicode、空白和明显格式，错字改写记录原文hash与改动；不删掉第二个诉求，不改写否定。只把脱敏后的单句及术语表发给教师模型，不发送会话历史、检索快照或数据库凭据。原数据库不就地改原话。冻结前用同一tokenizer按不截断方式检查长度；超过128 token的原句隔离并列出数量，不先截断再标注，测试冻结后不以过长为由删题。

### 4.2 目标规模与合成

目标是清洗去重后约2040个原始问题组（增强前），不是2040条真实客户问题。至少25%为2–3个明确诉求的多标签组；每类至少100个正例组，并包含相邻类边界、否定、短口语及错字。单标签和多标签分布、各类正例/反例、真实/演示/合成数量均进入报告。合成补足来自LLM按术语表生成，不用模板循环替换几十个名词凑独立样本数。

每个合成问题保存教师模型、prompt版本、请求ID、预期场景及家族ID，再进行独立预标注；不能直接把造数时指定的标签当成已正确标注。造数每项要求独立场景，改写明确保留父家族，不把一次请求ID当成所有问题的同义组。预标和场景不一致时进入复核，标签越界、重复、格式错误、空问题或未脱敏内容均隔离。达到10元上限即停止；不足目标时报告实际数量与缺口，不改数字、删难题或擅自加预算。

### 4.3 小批抽审与测试真值

先交付68条小批样本供用户抽审，覆盖17类、关键边界和至少17条多诉求句。由用户核对原句、预标标签、修订标签及疑难说明，保留样本ID、文件hash、审核人和回执。该批用于定稿标注规则和教师prompt，其同义家族只能进入训练侧；扩量须等抽审反馈，不能将“已生成抽审包”写成“人工审核通过”。独立功能开发和离线契约验证不受抽审等待影响。

留出测试集冻结后，再从中确定性抽68条人工复核，尽力覆盖每类至少2个正例及近邻、多标签错例；不足覆盖明确列出。人工修订后的集合为gold子集，其余LLM预标是silver；报告分别给出全量silver及gold结果和各自分母，不把全测试集称为人标金标准。真实来源单列，演示或来源未核实不算真实。

最终另输出最多34条去重错例复核包，优先覆盖各类FP/FN和多标签漏标/多标，用户可逐条保留或修正真值。人审未发生则交付状态写“待人工复核”。已冻结测试的修订仅新增报告版本，不据此重调当前模型；需要继续优化时使用新训练版本及新留出方案。

## 5. 防泄漏划分与训练集增强

先精确去重，再按相同逻辑轮次、同一合成种子/改写家族、明显近重复和同义原句建立group_id；相同类别但不同问题不合并成一个大组。完全相同文本却标签冲突先处理冲突。跨来源近重复也归同组。演示硬编码验收句及近重复家族单列为probe，不进入训练/验证/测试。

冻结seed、分组算法、数据hash及split清单后，以组为单位做多标签迭代分层，目标train/validation/test为80/10/10。已用于prompt定稿的小批组固定训练，剩余组根据总目标余量划分；真实组有至少5组时给验证/测试各保留至少1组。单组样本权重和多标签正例分布一起报告，不能只按某一个“主标签”分层。

不同组大小可能无法精确满足比例，允许各份问题数与目标相差不超过3个百分点，并列出逐类实际比例；达不到时数据预检失败，不随机反复抽到好看的测试集。目标测试和验证每类均有至少10个正例、10个反例；缺覆盖先在冻结前补数，不把缺类F1当作满分。测试清单冻结以后不因模型分数而移动题目。

仅对训练原句做同义词替换、句式微调，目标按固定seed、类目和单/多标签覆盖选择约25%的训练组，每个原句最多增加1条，保持原标签、家族和来源。保护否定、诉求动词、数值及型号；可能改变语义的改写隔离或重新审核。增强后再次跨集合查重，冲突增强样本丢弃。验证/测试不增强，80/10/10口径以增强前为准，增强数另报；不为凑增强数突破费用/尝试上限。

## 6. 教师模型与10元累计硬上限

沿用项目标准API的 `glm-5.3-flash` 做离线造数/预标；本步骤单独prompt与输出预算，不改线上模型或第九步配置。当前官方文档要求该模型开启thinking，采用 `reasoning_effort=low`，不发送不支持的关闭thinking参数。单次输出上限8192；每批最多16条，正文和输入有界，不因截断无限升预算。严格校验完整JSON、标签集合、ID对应和finish reason，截断不作成功训练数据。

费用账本持久化在本步骤受控运行目录，固定身份、10.00元上限、模型/端点、费率版本和所有物理尝试；进程互斥，先原子落预留记录再发请求。账本丢失、损坏或身份冲突拒绝继续，不能自动新建零账本绕过累计限制。不同工作树共用同一本批准账本，重试、修复和阶段切换不重置。

按2026-10-21官方标准价格以未缓存输入0.8元/百万token、输出2.8元/百万token保守记账，不以缓存折扣扩大预算；价格来源和版本归档。调用前采用模型最大输入窗口1,048,576和最大输出131,072计费上界预留，约1.206元/次，而不是把字符估算当精确token数。正常返回且完整usage可核对时结算并释放多余预留，思考输出计入，不漏算也不重复宣称实际账单；缺失或无法核对usage、超时和崩溃保留整个预留。不得仅凭“报错了”退回费用。

只有累计已结算额加全部未决预留再加本次预留不超过10.00元，才允许发请求。未知模型/费率、端点不符或上游用量超过预留均暂停并诊断。SDK隐式重试关闭，应用至多对单次暂时连接/限流故障重试1次，每次重新预留；余额不足、参数不兼容和结构化失败不自动循环。原批准累计最多300次物理尝试；2026-10-22用户明确回复“允许400次，费用仍最多10元”，仅将次数上限增至400。连续3次失败仍暂停，原账本、失败记录和未知预留全部保留。修订以绑定原账本身份的独立attempt-approval.json留痕，不改原批准标记或数据库历史。此预算只授权本步骤数据准备，不触发第九步收费评估或业务写操作。

## 7. 全参数训练与模型选择

官方模型卡要求BERT相关加载函数；采用AutoTokenizer和AutoModelForSequenceClassification加载同一固定HFL模型，`num_labels=17`、`problem_type=multi_label_classification`，使用float多热标签和BCE损失。不是softmax单选，也不是换底座。所有编码器及分类头参数参与优化，记录trainable/total参数及编码器权重前后hash以证明实际训练。

首版训练配置：最大长度128 token、动态padding、训练micro-batch 4、梯度累积4（有效batch16）、FP16、梯度检查点、AdamW学习率2e-5、weight decay 0.01、warmup比例0.1、最大梯度范数1.0、最多8 epoch。保留原模型dropout；训练seed及数据顺序固定。类别权重只从训练集统计，首版不自动启用极端正例加权。

先做同配置小批前向/反向资源预检，记录GPU峰值和样本吞吐；该步骤不是最终训练报告。OOM只允许降低micro-batch并增加累积以维持有效batch，保留全参训练和数据；不得静默冻结编码器、换小模型、换LoRA或租云GPU。batch1仍不可行或版本冲突时停止说明并询问用户。主机断电或温度/资源异常时保留checkpoint，不伪造完成。

每epoch同步验证和保存，按验证集macro-F1（固定0.5解码）选择最佳checkpoint，平分取较早epoch；早停patience2，至少0.001改善才重置计数，加载最佳checkpoint。保留最多2个训练checkpoint和独立最佳导出，不自动清理别人的目录。训练记录loss、micro/macro-F1、耗时、峰值内存及停止原因。关闭第三方训练遥测和自动上传。

最佳checkpoint确定后，仅在验证集为每类扫描阈值0.10–0.90、步长0.05，最大化该类F1；平分优先接近0.5、再较高阈值。某类正/负支持不足10时该类保留0.5并标记证据不足。阈值、解码规则与模型一起冻结；测试集不选阈值、不选epoch。

## 8. 评测、解码与验收口径

sigmoid逐类独立决策，先取前16类达到各自阈值的标签；有业务标签时不附加“其他”。仅其他达到阈值则输出其他；17类均未达阈值时输出 `needs_review`、空预测标签，不用argmax或关键词规则凑一个标签。“其他”是真实主题类，`needs_review`是模型处理状态，两者分开。评测时空预测按漏报计入，不从分母排除。

冻结留出集完整输出：每类support、precision、recall、F1、TP/FP/FN/TN；17张one-vs-rest的2×2混淆矩阵，行是真值阴/阳、列是预测阴/阳。不能用互斥17×17矩阵替代多标签评测。另报macro/micro-F1、全标签完全匹配率、Hamming loss、多标签漏/多标及needs_review率。零分母明确标记，不当满分。

全量silver、gold人工子集、确认真实子集、合成子集分开展示，标注依赖关系和小样本限制；人工集不是拿来再次调阈值的。用户未指定数值F1门槛，本步骤不编造“保证95%”；报告跑通和真实效果是否充分分别结论，低分类和未完成人审不得藏起来。

发布候选必须真实跑过完整留出报告，并通过独立probe中的“买大了想退”（恰好退换货+尺码）及近邻/否定例。probe输出来自实际导出模型；不能在接口里写规则特判。若关键多标签用例失败，保留失败证据并标记验收未达成，不给报告改标签。改进须新版本，不把测试错例直接回填后仍称原留出成绩。

## 9. 独立推理服务与产物契约

训练/推理重依赖拟放在 `ml/topic_classifier/` 独立项目，轻量清洗/术语读取和业务批处理拟放在 `app/topics/`。业务应用通过HTTP调用分类服务，不import torch。

导出包包括safetensors权重、tokenizer、17类label映射、阈值、清洗/解码版本及manifest。核心manifest固定底座revision、权重/tokenizer hash、taxonomy版本/hash、冻结数据/split/训练抽审回执hash、训练配置、seed和依赖lock hash；model_version由该核心规范JSON的SHA-256生成。评测报告引用model_version；外层发布清单再记录报告及测试人审回执hash，两者不反向参与model_version计算，避免“报告写模型版本、版本又hash报告”的循环。测试人审修订形成新报告版本，不改变同一权重/阈值的身份。服务启动严格核验整包，不下载远端模型、不加载任意pickle或trust_remote_code，不以随机分类头兜底。

服务默认CPU推理，`eval()`/inference模式，模型只在启动时加载。API为：

- `GET /health`：ready、model_version、taxonomy_version/hash和最大批量。
- `POST /classify`：调用方ID和文本数组，1–64条、每条1–512字符；返回同序ID、标签、17类概率、处理状态及模型/术语版本，不执行数据库写入。

超过长度拒绝，不默默截断第二诉求；本地清洗后若编码长度超过128也返回逐项 `input_too_long`，不把截断分类算成功。ID重复、额外字段、非有限概率或标签不在权威表均为契约错误。服务并发1、有界队列；满载返回明确busy，异常不外泄路径或原话。CPU批量时延先实测，工作进程超时默认60秒且可配置；不预设性能数字。

## 10. 业务批处理、迁移与追溯

保留用户原DDL，见附录A；新增独立补充迁移，仅给topic_classifications增加下列可空列，以便兼容仅建原表的环境：

| 补充列 | 类型 | 目的 |
| --- | --- | --- |
| model_version | VARCHAR(128) NULL | 标识实际权重、阈值和数据版本 |
| taxonomy_version | VARCHAR(96) NULL | 冻结术语版本及hash引用 |
| input_hash | CHAR(64) NULL | 识别问题被编辑后旧分类已失效 |
| batch_id | CHAR(36) NULL | 将落表结果对应到本地批次回执 |

为model_version建普通索引。原字段、unique(question_id)、FK及其删除语义不变。旧行新增列为NULL，页面列作“版本未知”；不追认成当前模型输出。迁移先preview/结构预检，拒绝有冲突的已存在表；迁移后核对InnoDB、utf8mb4、JSON、索引、FK，不能create_all静默绕过验收。MySQL DDL不承诺事务回滚，不自动删表或重建问题池。

旁路为独立Worker/CLI进程：默认每60秒检查一次，未分类数量达到20时按ID取最多64条；手动 `run-once` 可处理不足20条的明确范围。preview打印ID范围和总数，执行前冻结高水位和最大处理数；演示验收最多处理启动时现有100条池记录，不自动造问题写入业务池。后续新记录只由持续Worker下个批次处理。

每批持有独立MySQL命名锁，选择和落表沿用同一物理连接及所有权核对；推理时不长开事务。input_hash固定为数据库原始raw_question的UTF-8 SHA-256，不是脱敏后文本的hash；原文只留本机，推理使用对应清洗版本产生的脱敏文本。锁丢失不提交；SQL提交短事务内再次核对问题存在、input_hash未变、模型版本未变。question_id唯一保证同一原话流水最多一行；相同批次重放跳过已落表结果，崩溃后可恢复，不增加重复分类。

普通批次只处理缺行；旧模型、旧input_hash或版本未知结果标为待重新归类，不静默覆盖。更新旧分类须显式指定目标版本和ID范围reclassify，按question_id更新该唯一行，保存更新前后汇总回执。本步骤不新增模型结果历史表，旧版本完整结果保留在本地批次产物。

Worker验证health及每项响应的版本、ID、标签与概率。只对有效 `classified` 写labels；needs_review、过长、清洗失败及服务故障保留待处理并在回执记原因，不能落“其他”假成功。网络故障至多重试1次，已落表项不重新推理。失败回执以question_id/input_hash/model_version为键持久化在配置的本步骤运行目录：needs_review和数据错误等待显式retry，暂时故障按60/120/240秒退避，累计3次仍失败暂停该项等待retry，不用坏数据不断凑够20条空转；数据库或锁故障暂停本进程。回执不改问题池，不构成新的业务表。

退出时有界关闭HTTP和数据库资源；模型/数据库不可用只暂停旁路，不影响实时聊天。主聊天路径不注册此工具、不触发此worker、不写topic_classifications。

## 11. 主题分布页与统计

拟新增 `/topics`，从飞轮后台导航进入；现有 `/review`、`/observability`和聊天页面保留。前端按Vibe直接实现并在真实浏览器验证视觉、窄屏、空态和失败态。

页面显示当前模型/术语版本、问题池总数、当前有效已归类数、未有效归类总数、旧版本/输入失效数、最近归类时间；17类横向条形图按数量排序，类目为零也显示。待复核是未有效归类中的子集，从同一本步骤配置目录的有界、校验后回执摘要读取，并匹配当前input_hash与版本；回执不可用时该项显示未知，不用未分类数量冒充待复核数。统计是每类不同question_id数量，分母为当前有效已归类问题数：一问多标签可累计多次，比例总和可能超过100%，页面明确说明。不同入池入口的相同原话仍是不同question_id，此为问题池流水量，不冒称独立客户或去重知识缺口数。

默认仅统计配置中的当前模型与术语版本且input_hash匹配的结果，旧/未知结果单列，不混合比较；可按入池来源和日期范围过滤。点击类目分页查看脱敏问题、所有标签、来源、时间及模型版本，可定位原飞轮缺口；原始带隐私文本不进入静态HTML或页面源码。

只读统计使用现有本地后台访问限制和有界分页。表未迁移、无模型、服务未启动、尚未归类、SQL故障分别显示可理解状态，不把失败渲染成0条成功。页面刷新只读数据库，不隐式训练、调用LLM、重新归类或改变审核状态。本步骤不增加训练控制台或数据标注后台。
