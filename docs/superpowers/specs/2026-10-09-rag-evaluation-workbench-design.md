# RAG 评估工作台与 300 题评估设计

日期：2026-10-09。状态：用户于 2026-10-10 以“确认”批准本文，进入实施计划编写；尚未进入后端实现。

## 1. 用户目标与边界

用户要验证 vector、bm25、hybrid、hybrid_rerank 的实际效果，分别观察检索段与生成段，判断检索设计是否合适。评估材料为喵喵优选四篇知识正文，加授权补写的四篇演示规则；五类问题各 60 题，共 300 题。后台需要能运行评估、查看进度和历史报告，并逐题追溯证据、答案与裁判理由。

用户关键决定：先“补齐文档后再评估”，随后授权“我也不知道，你自己编写一下”，最终同意保留原题及修订记录、独立语料建库、统一内容自评、复用评估器和单批运行管理的方案。本次是第四步的评估扩展。分支仍为 feat/hybrid-retrieval，不使用 ch 命名分支，不隐含合并或推送。

固定技术：Python、FastAPI、SQLAlchemy、Docker MySQL、Milvus 原生 BM25/chinese analyzer/hybrid_search RRF、BGE-M3、bge-reranker-v2-m3。沿用当前锁定版本、模型、密钥来源与已批准预算；不引入新任务队列、另一个数据库或另一套检索引擎。后端按 Superpowers，前端按用户指定 Vibe Coding，资料与 Prompt 用样例核验替代代码 TDD。每个函数有中文说明，文件 UTF-8。

本次不做：部署级多租户后台、分布式调度、断点自动续跑收费模型、重新校准线上 MH 门槛、修改正在聊天的知识库、服务端满意度反馈、额外 Agent 循环。

## 2. 已有实现与事实基线

- app/retrieval/service.py 已统一四路检索。内部 dense 展示为 vector，其余策略名保持。每路候选上限 50，最终证据上限 10；混合调用服务端 RRF，重排在混合候选上执行。
- evals/evaluate_retrieval.py 已有真实评估、一次问题理解供四路复用、最多两题并发、逐项保存、最终流校验、裁判与自有资源清理。现行金标为物理块集合，不能表达跨小节的 AND/OR 证据组。
- SufficiencyService 当前对 hybrid_rerank 额外要求校准分门槛，其余路只做内容自评。旧 .82 左右门槛来自 XM 合成语料，不能作为新 MH 语料的有效校准。
- 当前 8001 聊天库为旧 84 块 XM 合成资料。真实历史比较为 30 题、120 条策略记录，101 完整、19 错误。不得把这些结果当成新 300 题结果，或将失败项填成满分。
- 新八篇资料在 knowledge-docs/evaluation-drafts，未导入。现有切分器 target_chars=1200、overlap_chars=120 得到 50 块：7/14/13/9/2/2/2/1。块数由文本和配置决定，不强凑教程 51/52。
- 已有 /static/rag-evaluation.html 预览，可读旧报告并查看指标、筛选与详情。新建按钮禁用。预览是前端成果，任务管理后端尚未完成。

## 3. 材料、金标与冻结方式

### 3.1 知识规则

八篇资料作为本项目演示制度，补写部分明确记来源和授权，不表示真实商家规定。入库文件白名单排除 README。会员按有效累计消费升级，沿用原 FAQ；新增门槛、生日礼、积分、开票与猫窝清洗规则与该口径一致。对未定义的到账、附加运费金额、设备断网行为等保持未知，不补承诺。

原文、切分参数、每篇 SHA-256、每块稳定内容标识和完整原文一起冻结。报告记录实际块数，不依赖数据库自增 ID 来识别语料版本。模型不能从金标得到生成答案；生成输入仅用户问题和本策略实际检索证据。

### 3.2 保留原题，逐条审标

保存用户原 CSV 为不可修改基线；另生成 reviewed CSV、运行用 JSONL 和变更说明。所有 300 题须检查章节、必需事实、作用域、可答性与桶类型，不能仅检查已发现项就宣称全审完成。

修订版仍五桶各 60 题，ID 唯一。原 D_absent 映射到现有内部 D_unanswerable，展示为库外问题。每条记录保留原 query/标签与修改理由，不能无记录覆盖原题。

具体纠偏：

- A21/A22/E16/E57 涉及“年消费”时，回答澄清累计消费口径；标准点包含适用口径，不只匹配金额。
- D3 纸质票、D30 日本配送已有依据，不再作为库外拒答金标。将其保留为额外可答回归样例，用真正未覆盖的业务问题替换 D 桶相应题位，记录新旧题及原因。
- B54–B57 两型号比较按两个必需证据组计分，不能 OR 任中一款就算答全。
- 修订 E 类中只有单小节便足够回答的题目，增补确实需要第二小节的子问题，使 60 道 E 题均需要两个或以上独立小节。不得用无关章节点强行构造跨文档要求。
- 预售不必答“48 小时”；布艺猫窝不能套电子类“保修 12 个月”；断网、配网、洗坏是否属于质量等无完整依据的子问题要明确未知，不能把常识当金标。
- 开票完成时间与退款到账、维修处理时限分别标注，不偷换概念。章节别名人工映射至实际章节，不用字符串 contains 评分。

### 3.3 证据组与答案要点

expect_section 先按 + 分组，组内按 | 列出可替代章节。每组都需命中，组内任一章节命中即满足该组。例如“退货政策 | 适用范围 + 退换货运费承担 + 退款时效”有三组。映射产物显式列出每组的稳定源引用、对应物理块 ID 和来源原文；别名不能匹配时在任何云端请求前失败。

若一节被切成多块，明确哪一块或哪组子块足以支撑该题要点，不能把同章任意块都当完整证据。运行 JSONL 显式保存已审定的组成员，不在运行时猜章节。

expect_points 的 | 是分隔多个必需事实，不是任选。解析为带 point_id、要点、适用条件和可接受同义表达的列表。E 类每个子问题都必须有对应要点。未知子问题的正确处理也可成为必需点，如“资料未说明，不能承诺”。

冻结失败条件：行数/桶数量不符、ID 重复、空正例金标、库外题含可回答金标、映射不到原文、E 类不足两个独立必需组、没有变化理由的修改、非法品类条件或 UTF-8 错误。先离线阻断，不消耗模型调用。

补写知识参考了这份题库，因此结果是项目内受控演示比较，不能宣称独立未知数据上的泛化能力。分桶试运行抽样固定并保存，不挑“分数好”的样例。

## 4. 四策略的公平比较

### 4.1 检索侧

| 展示策略 | 执行规则 |
| --- | --- |
| vector | BGE-M3 对规范问题做 dense 编码，COSINE 召回前 50，取前 10 |
| bm25 | Milvus BM25 对规范问题、检索侧同义扩展和完整原话检索，取前 50，再取前 10 |
| hybrid | dense 前 50 与 BM25 前 50，经 Milvus hybrid_search 的 RRFRanker 融合成前 50，再取前 10 |
| hybrid_rerank | 同一混合流程前 50 候选，用 bge-reranker-v2-m3 重排取前 10 |

四路共享一次问题理解、相同原话、品类条件、语料版本和 Prompt。保留当前密集问题向量与稀疏文字展开的差异，不伪称四路输入格式相同。问题理解改写不得读取标准答案，品类过滤先验证再执行。共享改写耗时仍独立扣入各策略 FAQ/聊天剩余期限，后执行的策略不承担前一策略的耗时。

候选、最终前十、实际装入 Prompt 的证据分别记录。已有最相关放首尾的证据排布、引用编号和输入预算裁剪四路一致；评估 Prompt 证据覆盖用实际供给的证据，不拿召回前十冒充。

### 4.2 生成侧

本次固定模式名为 content_ablation：四路执行相同的内容充分性自评，不使用某一路特有的分数阈值。空证据仍拒答，事实问题不能伪装社交/澄清绕过守卫。SufficiencyService 将“内容判断”与“线上评分门槛”分离，默认线上行为及必需校准保持，只有显式评估模式采用共同内容门槛；不伪造 strategy 字段避开检查。

报告醒目标注这是检索策略消融，生成门槛与线上 calibrated_score 模式不同。不得用此结果声称线上已校准；此次不启用新 MH 语料服务。以后若评线上门槛，需单独校准与单列实验，不混入本轮四路对比。

沿用 GLM 模型与零重试；最终回答上限 512 token，问题理解/自评各 2048；问题理解期限 60 秒、自评 20 秒，其余采用当前配置并记录，包括裁判上限、FAQ/聊天期限。非法结构化输出、截断、超时、取消、引用非法和流未正常完成均保留为错误，不作为拒答。不得为了跑满而自动提高预算或换模型。

### 4.3 新指标

对每题的候选 ID 与最终排名先去重。库外题不计正例检索分母。

- MRR@10：前十中首次命中任一已审定相关证据的 1/rank，无命中为 0。它不表示多组已凑齐。
- Group Recall@5/@10：前 K 中满足的必需组数 / 全部必需组数。替代章节只计该组一次。
- All-groups-hit@5/@10：全部必需组满足为 1，否则 0。用于跨小节完整性。
- Candidate Group Recall@50：召回阶段的组覆盖。对重排策略使用重排前候选，不把最终十条当候选五十。
- Prompt Group Recall：实际提供给生成模型的证据满足比例，与检索排名指标分开。
- Answer point coverage：回答满足的全部适用要点比例。拒答正例记 0；未知子问题需如实说明。通过严格结构化裁判逐点判定、记录原答案与理由，支持同义表达，不能只做字符串匹配。
- Faithfulness：本题回答事实断言中获实际证据支持的比例。联合裁判同时列出全部断言与逐点覆盖，禁止把标准答案当支持证据；零断言为不适用，不能把纯拒答计 1。
- 库外拒答率、可答误拒答率：按合法有效生成结果计，错误另外展示；也报应答总数、有效数、错误与未执行，避免低有效率下的 100% 误导。部分可答问题不当完整库外题。

联合裁判使用当前裁判模型、2048 上限及严格 JSON 验证，逐条 point_id 必须完整且唯一，布尔类型严格，原始 finish_reason 必须 stop。漏项、截断、非法输出算 judge_error。保留 Prompt 版本、原响应与理由；不会静默使用旧忠实度分填新覆盖指标。原 v1 报告仍按原口径展示，不回算或回填其不存在的指标。

宏平均：先对每题算指标，再在每桶和总体按适用题平均。每项自己的有效分母与排除原因同时输出；检索已经完成而后续裁判失败，仍可保留检索指标。生成总体比较额外给出四路共同有效题子集的指标与题号，避免仅各自成功子集导致选择偏差。报告指出小样本、缺失项和模型裁判局限，不预设重排获胜，也不宣称相对结论永久不变。

## 5. 执行服务与资源责任

### 5.1 组件

1. Dataset loader/validator：加载服务端白名单冻结资料与 JSONL，校验全部金标、章节映射和哈希；返回不可变运行输入。
2. 共用评估执行器：复用检索/证据/生成/流守卫和严格裁判，新增证据组指标与联合裁判适配；CLI 和 HTTP 调同一个入口。旧 CLI 与原报告格式通过兼容分支保留。
3. Run store：在 runtime/rag-evaluation/runs/<run_id>/ 保存 manifest、完整报告与 Markdown 导出；此运行目录加入 Git 忽略。文件原子替换，单一写入者更新；公开 API 使用白名单 DTO，不返回密钥、模型请求正文、连接串或内部栈。
4. Run manager：由 FastAPI lifespan 拥有，保存任务引用和单运行锁；将执行、取消、异常及清理汇入持久状态。进程内异步执行，运行期不占用请求会话或长数据库事务。
5. HTTP router 与静态工作台：以运行 ID 查询摘要、分桶指标与分页逐题详情，前端轮询状态。历史预览可导入只读 v1 记录，清楚区分语料/指标/门槛版本。

不选择只有静态报告的路径，因为不能从后台运行和取消；不引入分布式任务队列，因为当前只需单运行。支持单 Uvicorn worker；多 worker 不宣称共享内存锁足够。CLI 和后台共用本地排他运行锁，冲突立即拒绝，不能两边同时消耗模型。

### 5.2 资源隔离与清理

真实评估沿用本机 3308/customer_service_test 及新 UUID Milvus 集合，禁止指向 3307 业务库或 knowledge_hybrid。读取上游配置，数据库凭据仍来自本地配置。无可用隔离库时明确失败，不自动切到业务库。

只导入八篇白名单材料，导入前做全部离线金标验证。MySQL 先写 pending，再经 BGE-M3 写 Milvus、回填 done，沿用主键幂等和权威原文。实际映射保存逻辑标识与本轮物理 ID。

本轮自有 MySQL ID 在短事务 flush 后、commit 前写入持久 ownership manifest；manifest 写入失败则不提交该批事务。独立集合名在创建前记录。这样进程中断时可按已记录归属回收，而非扫描删除其他测试数据。资源清理仅凭本轮 manifest 的 ID 和 UUID 集合，禁止删除整个测试库或任意前缀集合。

正常、取消、异常均有独立有界清理，报告保留实际证据全集，即使临时块已删除仍可追溯。有效编造记录沿用 faith_cases 留存，并在报告保留每策略快照；不将取消或非法裁判写成编造。临时低置信问题不写入在线用户池，改留本轮报告。

新题库台账键采用题面稳定哈希前十位与原短题号组合，总长度不超过现有 eval_id 的 16 字符限制，冻结时检查碰撞。相同题面跨轮累计，题面被替换时不能冒充同一道复发个案；报告仍展示用户原题号及 dataset_id/run_id。旧台账键和历史记录不重写。

进程重启把非终态记录标为 interrupted，停止自动收费续跑；先按 ownership manifest 尝试有界清理，记录每项结果。归属无法证明的资源不自动删除，标为 cleanup_unverified；清理失败不能宣称干净完成，也不能无记录丢弃。

### 5.3 运行状态与进度

状态：queued → preparing → running → completed 或 completed_with_errors；初始化失败为 failed，取消经过 cancelling 才到 cancelled，进程中断为 interrupted。终态写在清理结果确定之后。completed 要求全部策略有效完成且清理成功；completed_with_errors 表示全量已处理但存在保留的单题错误。

任何清理失败使运行状态为 failed，并保留原本的评估/取消状态和 cleanup_errors；不能仍展示干净的 completed 或 cancelled。单题数全部处理不等于资源全部释放。

run_id 为服务端生成 UUID，请求不能提供输出路径、集合名、数据库地址、任意模型名或阈值。快照记录 dataset_id/语料与题库哈希、模式、配置预算、开始/结束时间、计划题数、计划策略数、阶段、完成/错误/未执行数、实际请求数、清理状态及每题详情。

每道题唯一改写失败时四条策略记录都明确标为共享 rewrite_error，HTTP 请求计数只增加实际调用次数；不能展示四次改写。取消未开始项记 not_attempted，已开始中断项记 cancelled，不能混同业务拒答。进度标明建库/检索/生成/裁判/清理阶段，全量完成计数不能替代清理结果。

## 6. 接口与工作台

| 接口 | 行为 |
| --- | --- |
| GET /rag-eval | 按用户补充的验收截图返回工作台页面；现有静态预览地址保持 |
| GET /api/rag-evaluations/datasets | 返回已冻结语料/题库版本、实际块数、可运行范围及匹配试运行状态 |
| POST /api/rag-evaluations/runs | JSON {dataset_id, scope: pilot或full}；校验后返回202与run_id；忙返回409，不隐式排第二个收费任务 |
| GET /api/rag-evaluations/runs | 分页历史摘要，包含旧只读报告及新模式标签 |
| GET /api/rag-evaluations/runs/{run_id} | 状态、配置快照、计数及汇总；不存在404 |
| GET /api/rag-evaluations/runs/{run_id}/cases | 按桶、策略、状态、关键词分页，不重算模型 |
| GET /api/rag-evaluations/runs/{run_id}/cases/{eval_id}/{strategy} | 本次问题、金标组、候选/排名、实际Prompt证据、答案、逐点覆盖、断言裁判和错误详情 |
| POST /api/rag-evaluations/runs/{run_id}/cancel | 幂等取消请求；终态返回已有状态，不重启或删除历史报告 |
| GET /api/rag-evaluations/runs/{run_id}/export | 白名单 JSON/Markdown 报告下载，不接受文件路径 |
