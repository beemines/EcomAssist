# 第九步参考页面差距与验收基线

2026-10-20，按用户提供的18张验收截图，对照 `feat/observability-flywheel` 当前实现、8006页面和已保存的真实运行结果。用户要求：“这是标准的验收过程和页面，对比一下不足的地方，以这个为标准”。

**按这套标准，当前尚未完整验收通过。** 三入口落池、原轮证据保存、标准化归并、人工审核发布、新会话检索回答已跑通；评估可靠性、误放控制、trace摘要、金额成本和管理页面仍有缺口。此前的本地交付与自动测试通过，不等于这些新增标准已经满足。

## 必须先解决的质量问题

**两轮评估尚不足以证明质量稳定。** 已跑两轮各20题，分别成功11题、12题，错误9题、8题。两轮共13个裁判请求出现 `finish_reason=length` 且有效内容为空，另有4个生成阶段错误尚未完全定位。Faithfulness均为1.0，但有效分母分别只有7和8；Recall@10和MRR有效分母均为16。不能把这些结果展示成“20题全过”或“全量评估稳定”。

**置信度目标需要按新标准调整。** 当前新规则留出集误拒1次、误放6次；旧规则误拒22次、误放2次。新规则减少了误拒，同时增加了误放。参考要求优先压住误放，当前结果不能视为达标。调整时保持校准集与留出集隔离，不用留出标签反复选阈值；页面应同时呈现两个集合的结果与样本分母。

**金额成本确实缺实现。** `intent_usage.py` 将 `currency_cost` 初始化为 `None` 且未汇总金额；页面相应显示N/A。Langfuse支持按usage与模型价格计算成本，并支持自定义模型定价；GLM的模型匹配和价格来源需要核实后接入，历史无可靠价格的数据继续显示未知，不能补成零。[Langfuse成本跟踪官方文档](https://langfuse.com/docs/observability/features/token-and-cost-tracking)

## 已有能力应保留

- 三个实际入口：检索低置信度、生成自评不足、用户负反馈。原轮👎幂等重放不会重复建池记录；同轮跨入口保留来源但不重复累加同一缺口出现次数。
- 问题入池时保存原轮片段，事后反馈尽力从原轮回捞；没有用当前知识重新检索冒充当时证据。
- 原话归并后可追踪；人工审核与知识发布分开，向量就绪才显示可检索；失败保留同一知识ID供人工重试。
- 按最终意图归属分类前的模型消耗，按generation汇总避免父子重复记账；聊天、后台、评估用途分开，缺usage不记作零。
- 两轮独立运行、独立原始报告、同配置分组，错误和有效分母如实展示。

截图中快照为JSON数组，当前保存带状态和chunks的JSON对象。两者应按“原话对应的原轮证据能否核对”验收；对象外层不同不构成功能缺陷。截图所述“只能按tags统计”也不能直接作为当前版本API限制；应保留现有metadata归属，同时补可见标签。[Langfuse标签官方文档](https://langfuse.com/docs/observability/features/tags)

## 后续修正顺序和验收动作

1. **评估可靠性和误放控制。** 复现裁判length及生成错误，确认错误来源与输出结构；明确零误放优先的校准选择目标，再验证留出表现。不得用隐藏错误、改分母、把失败补为满分来通过验收。
2. **Trace和金额。** 新建一条知识问答、一条工具问答；从顶层即可读原话与最终回答、会话、意图标签、输入输出Token、耗时和可靠成本，展开能看检索与工具。校验汇总没有重复计数。
3. **待审与飞轮。** 两种同义问法归并一项并累加；详情核对来源、时间和原片段；草稿预填但由人工修改确认；驳回后重复问仍归并原项且保持驳回；核准后向量就绪，新会话重问拿到有依据的回答。另测一次👎后端落池。
4. **观测与校准页面。** 补独立入口、概览、单均、占比、更新时间、趋势差值、下降提醒和作业进度；补校准分布、阈值扫描、在用规则和误放误拒解释。
5. **完整演示。** 按参考串起“启动→问答trace→缺失知识→问题池→归并→人工核准→就绪→新会话答对→负反馈→成本→两轮评估→阈值依据”，保留截图、SQL/API记录及逐题报告。全量300题生成与收费定时属于尚未执行范围，先修失败，再在明确的调用额度内安排。
