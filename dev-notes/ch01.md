  - [trim_messages](https://reference.langchain.com/python/langchain-core/messages/utils/trim_messages)：支持 strategy、start_on、include_system、allow_partial 和 token_counter；近似计数适合需要快速裁剪的路径，不能宣称等于所有模型的真实 tokenizer 计数。
  - [模型流式输出](https://docs.langchain.com/oss/python/langchain/models)：流返回 AIMessageChunk，每块包含部分文本，可以聚合为完整消息；SSE 立即转发上游文本增量，不把整段回复生成后拆字发送，不声称每个块恒等于一个 token。
- 两种上下文方案对比：推荐 session_id + 服务端进程内存，适合本章 curl 验收；备选为客户端每次提交完整历史，服务端无状态，但把历史维护交给调用方。两者均保持既定技术栈及直连上游。
- 推荐设计的接口契约：
  - POST /api/chat：请求 session_id、message；响应 text/event-stream，事件 delta 携带新增文本，成功以 done 结束，失败以 error 结束。
  - POST /api/extract：请求 text；返回 order_id、request_type、expected_solution 三个字段。
  - GET /health：验证应用启动状态，不将其成功视作模型连通验收。
- 会话规则：进程内按 session_id 隔离；成功生成完整回复后才保存本轮；失败或断开不保存半轮；同一 session_id 同时发起两次生成时返回会话忙，避免历史乱序。开发演示以单进程运行，重启后历史清空。
- 预算规则：保留 system 与当前用户消息，按保守 token 估算删除最旧的完整轮次；输入预算和输出上限分别可配置；固定必留内容超预算则明确报错，不偷偷截断用户当前问题。实际验收记录近似计数的限制。
