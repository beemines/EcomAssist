- 用户纠偏与约束：本机存储占用是部署选择的重要约束；SDK 和后端镜像版本仍需分别锁定，不能把最新网站示例直接当作项目已安装 API。实测现有运行环境的 LangGraph 为 1.2.15、langchain-core 为 1.6.6。
- 翻车与返工：早期按主仓库 `.venv` 猜测安装源码位置未命中，已用实际运行 worktree 的 Python 包元数据查出正确路径。评估仓库同时保留旧物理 chunk 与新版完整证据组口径，趋势必须标记数据集、指标定义和有效分母，不能把两套同名历史分数连成同一曲线。尚未安装 Langfuse、部署容器、调用收费模型或修改数据库。

## 2026-10-19 · 本地部署方向确认与资源基线

- 用户关键原话：“那弄一个本地的吧”。据此确定本章使用本机 Docker Compose 自部署 Langfuse；未采用 Cloud 托管，数据自管要求保留。这次答复确认部署方向，正式 spec 和实施 plan 仍待后续审阅。
- 关键产出：本机 C 盘剩余约 191 GB、D 盘约 154.2 GB。Docker Linux Engine 可见内存约 15.46 GiB，当前五个运行容器内存合计约 1.35 GiB；现有镜像 3.649 GB、卷 1.513 GB 为新增占用对照基线。Milvus 使用宿主 9091 / 19530，MySQL 使用 3307 / 3308，新部署须避开。查询官方公开元数据得到 SDK `5.0.2`（Python >=3.11）、服务端 `v4.63.0`（2026-10-16 发布），将继续按固定版本源码核对，不在设计阶段安装。
- 用户纠偏与约束：前述 10～20 GB 占用 / 30 GB 预留仅为部署前规划估算，不是官方要求或实测结论；实施后应报告实际新增镜像和数据卷占用。服务器月预算 30 元没有转为任何云端购买动作。
- 翻车与返工：普通沙箱读 Docker named pipe 和外网元数据被权限限制，改用只读受限提升后成功；这不是 Docker 服务故障。CIM 内存查询不可用，因此使用 Docker Engine 配额及容器 stats，不把 CIM 失败当成内存不足。至此没有启动、停止容器或拉镜像，没有改数据库，也没有发起收费模型调用。
